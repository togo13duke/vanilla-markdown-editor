# sprint.md — スプリント計画とマイルストーン

前提
- 1 sprint = 1週間想定（調整可）
- “動くもの優先” だが、XSSとデータ消失だけはMVPからブロッカー扱い
- スプリント構成は学習パスの提案（全6回）に沿う

## Milestone 0（準備）
- リポジトリ作成、Vite導入（または素のESM）
- 最低限の画面骨格（Header/Sidebar/Main）
- コーディング規約（ESLint/Prettier）設定

完了条件
- `npm run dev` で起動、静的UIが表示される

---

## Sprint 1: UIレイアウト（Grid / Position / Resize）
目的
- アプリの情報設計を確定し、以降の機能追加の土台を作る

スコープ
- 3ペインレイアウト（Files / Editor / Preview）
- モバイル時の縮退（Editor/Preview切替）
- ResizeObserverで閾値切替（例: < 600px）

成果物
- UIが破綻しない骨格
- CSS Variables + prefers-color-scheme（簡易ダークモード）

リスク
- 先にUIを作り込みすぎる
対策
- “見た目”は最低限。操作可能性（クリック領域/スクロール）を優先

---

## Sprint 2: Markdownパーサ（正規表現・サブセット）
目的
- Markdown → 安全なHTMLの変換ラインを確立

スコープ
- 見出し、太字、斜体、リンク、コードブロック
- エスケープ処理（XSS対策）を先に実装
- 仕様外入力でも落ちない

成果物
- Editor入力 → Previewに反映（メインスレッドでも可）

完了条件（DoD）
- `<script>` 等が入力されても実行されない（危険文字がエスケープされる）

代替案
- 外部ライブラリ導入（marked等）
  - ただし学習目標からは後退。採用する場合は理由を明文化

---

## Sprint 3: ファイル管理（IndexedDB / File API）
目的
- “複数ファイルを扱える” 状態を作る（上級要件の中核）

スコープ
- IndexedDB CRUD（作成/更新/削除/一覧）
- アクティブファイルの切替
- エクスポート（.mdダウンロード）
- （任意）インポート（.md/.txt）

成果物
- ブラウザを閉じても復元できる

リスク
- IndexedDBの非同期・upgrade地獄
対策
- Repository層に閉じ込め、UIに露出させない

---

## Sprint 4: 自動保存・デバウンス・ショートカット
目的
- 執筆体験の品質を上げる（ストレス要因を潰す）

スコープ
- 入力のデバウンス（previewとautosaveは別タイマー）
- Cmd/Ctrl+S保存
- Cmd/Ctrl+B太字など最低限
- トースト通知（保存完了/エラー）

成果物
- 体感として「エディタらしくなる」

完了条件（DoD）
- 連続入力しても固まらない
- リロード後に直近内容が復元される

---

## Sprint 5: Web Worker + パフォーマンス最適化
目的
- 長文でも入力が止まらない構造にする

スコープ
- markdownパースをWorkerへ移管
- requestIdで古い結果の破棄（最新勝ち）
- 簡易メトリクス（parse時間等）をconsole出力（任意）

成果物
- 5,000文字以上でも入力遅延が顕著に増えない

リスク
- worker導入でデバッグが難化
対策
- まずメインスレッド版を残し、フラグで切替可能にする（開発時）

---

## Sprint 6: エクスポート拡張・Clipboard・UX仕上げ
目的
- 実用機能と品質の穴埋め

スコープ
- Clipboard API（コピー/ペースト支援）
- Outline（見出し抽出＋クリックジャンプ）
- エクスポート拡張（.htmlは任意）
- エラー表示の整理、設定（テーマ）

成果物
- デモとして完成度がある

完了条件（最終DoD）
- 主要ユースケース手順が破綻しない
  1) 新規作成→編集→自動保存→リロード復元
  2) 複数ファイル作成→切替→それぞれ保持
  3) エクスポートで.mdが取得できる
  4) 危険な入力が実行されない（XSS耐性）

---

## 補足：スコープ調整の指針（現実的な落とし所）
削る優先順位（削っても価値が落ちにくい）
- MutationObserver（Outline生成は解析結果で十分）
- インポート機能（エクスポート優先）
- 設定画面（テーマはトグルで十分）

削れない（中核価値）
- IndexedDBの複数ファイル
- 自動保存
- XSS対策
- 入力の滑らかさ（最低限のdebounce、可能ならworker）
