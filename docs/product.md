# product.md — Vanilla Markdown Editor（Why）

## 1. ビジョン
「ブラウザだけで、Markdownの作成・整理・出力まで完結する。高速で途切れない執筆体験を、Vanilla JSで実装する。」

本プロジェクトは学習パス上の上級課題として、リアルタイムプレビュー、ファイル管理、自動保存、エクスポートを中核価値に据える。

## 2. 目的
- Markdown執筆の基本動線（作る→整理する→確認する→出力する）を一画面で完結させる
- パフォーマンスと堅牢性（入力の滑らかさ、データ消失耐性、XSS等の安全性）を設計・実装で担保する
- Vanilla JSで「構造設計」「状態管理」「非同期」「ブラウザAPI統合」を総合的に鍛える

## 3. ターゲットユーザーとニーズ
主対象（一次）:
- 学習者 / フロントエンド中上級者
  - ブラウザAPI（File/Clipboard/IndexedDB/Worker/Observer）をまとめて実戦投入したい
  - フレームワーク無しでアーキテクチャ設計を経験したい

副対象（二次）:
- 日常的にMarkdownを書くユーザー（メモ、議事録、README）
  - 複数ファイルを軽量に管理したい
  - すぐプレビューしたい
  - ローカルに安全に保存して持ち出したい

## 4. 提供価値（Value Proposition）
- 「入力が止まらない」リアルタイムプレビュー（デバウンス + Workerでのパース）
- ファイル単位で保存・切替できる（IndexedDB中心、LocalStorageは補助）
- “ローカル完結” の安全性（サーバ送信なし、権限はユーザー操作ベース）
- 重要操作がショートカットで完結（保存、太字等）

## 5. 主要機能（MVP → Plus）
MVP（必須）
- 2ペイン（Editor / Preview）+ ファイル一覧
- Markdown基本記法のレンダリング（見出し、強調、リンク、コードブロック）
- 自動保存（デバウンス）と復元（起動時ロード）
- ファイル作成 / リネーム / 削除 / 切替
- エクスポート（.mdダウンロード）

Plus（余力/拡張）
- アウトライン（見出しから生成、クリックで該当位置へ）
- クリップボード（コピー/ペースト支援）
- インポート（.md/.txt読み込み）
- レイアウト可変（リサイズ、モバイル時の切替）
- 操作トースト/エラーUI、設定（テーマ等）

## 6. 非目標（Non-Goals）
- リアルタイム共同編集（WebSocket等）
- 完全なMarkdown仕様準拠（CommonMark完全対応）
- サーバ同期、ログイン、クラウドストレージ連携
- WYSIWYG（リッチテキスト）エディタ化
- プラグインエコシステム

## 7. 成功指標（Success Metrics）
体感品質
- 通常入力で「キー入力遅延を感じない」こと（目安: 入力→プレビュー反映 p95 < 150ms）
- 5,000〜20,000文字規模で破綻しない（スクロール/入力が継続可能）

信頼性
- 自動保存で内容が失われない（クラッシュ/リロード後の復元率）
- ファイル切替で誤上書きしない

品質
- セキュリティ事故（XSS）を設計上封じる
- 主要ユースケースのE2E相当を手動テスト手順で再現可能

## 8. 主要リスクと対策
- Markdownをregexで処理すると境界ケースで破綻しやすい
  - 対策: 対応範囲（subset）を明確化し、仕様外入力は「崩れても落ちない」を優先
- innerHTML使用によるXSSリスク
  - 対策: 生HTMLを許可しない。出力は必ずエスケープ→安全なタグのみ生成
- IndexedDBは実装が煩雑
  - 対策: 薄いラッパ層（Repository）を用意し、UIから隔離

## 9. 代替案（トレードオフ）
- 外部Markdownライブラリ（marked等）を使う
  - メリット: 仕様準拠と保守性
  - デメリット: 学習要素（正規表現/Worker設計）が薄れる、依存増
- 保存をLocalStorageのみで済ませる
  - メリット: 実装が簡単
  - デメリット: 容量制限・構造化データに不向き（複数ファイルで破綻）
