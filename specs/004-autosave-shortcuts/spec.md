# Feature Specification: 自動保存・デバウンス・ショートカット

**Feature Branch**: `004-autosave-shortcuts`
**Created**: 2025-12-28
**Status**: Draft
**Input**: User description: "Sprint 4: 自動保存・デバウンス・ショートカット - 執筆体験の品質を上げる（ストレス要因を潰す）"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 自動保存によるデータ保護 (Priority: P1)

ユーザーがエディタで文章を編集しているとき、明示的な保存操作をしなくても、一定時間の入力停止後に自動的に内容がIndexedDBに保存される。これにより、ブラウザのクラッシュやタブの誤閉じによるデータ消失を防ぐ。

**Why this priority**: データ消失はユーザー体験において最も深刻な問題であり、信頼性の基盤となる機能。これがないと他の機能の価値が損なわれる。

**Independent Test**: エディタに文章を入力し、入力停止後にブラウザを強制終了してから再度開き、内容が復元されていることを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーがエディタで文章を編集中, **When** 入力が700〜1200ms停止する, **Then** 現在の内容がIndexedDBに自動保存される
2. **Given** 自動保存が完了した, **When** ブラウザをリロードする, **Then** 保存された内容がエディタに復元される
3. **Given** 自動保存が失敗した（IndexedDBエラー等）, **When** エラーが発生する, **Then** ユーザーにエラー通知が表示され、isDirtyフラグは維持される

---

### User Story 2 - デバウンスによる滑らかな入力体験 (Priority: P1)

ユーザーが高速でタイピングしているとき、プレビュー更新と自動保存の処理が入力を妨げない。デバウンスにより、連続入力中は処理を遅延させ、入力が止まってから処理を実行する。

**Why this priority**: 入力の滑らかさはエディタの基本品質。これが損なわれると執筆体験全体が劣化する。

**Independent Test**: 5,000文字以上の文章を高速入力し、入力遅延やUIのフリーズが発生しないことを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーが連続して入力中, **When** キーストロークが続く, **Then** プレビュー更新は100〜250msのデバウンスで遅延される
2. **Given** ユーザーが連続して入力中, **When** キーストロークが続く, **Then** 自動保存は700〜1200msのデバウンスで遅延される
3. **Given** プレビューと自動保存が別々のタイマーで管理されている, **When** 入力が停止する, **Then** プレビューが先に更新され、その後自動保存が実行される

---

### User Story 3 - 手動保存ショートカット (Priority: P2)

ユーザーがCmd/Ctrl+Sを押すと、現在のファイルが即座に保存される。これにより、重要な編集ポイントで明示的に保存したいユーザーのニーズに応える。

**Why this priority**: 自動保存があっても、ユーザーが「今保存した」という安心感を得られる手段は重要。ただし自動保存が機能していれば必須ではない。

**Independent Test**: エディタで編集後、Cmd/Ctrl+Sを押し、保存完了通知が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーがエディタで編集中, **When** Cmd/Ctrl+Sを押す, **Then** 現在の内容が即座にIndexedDBに保存される
2. **Given** 保存が成功した, **When** 保存処理が完了する, **Then** 「保存完了」のトースト通知が表示される
3. **Given** Cmd/Ctrl+Sが押された, **When** ブラウザのデフォルト保存ダイアログが開こうとする, **Then** デフォルト動作がキャンセルされ、アプリ内保存のみが実行される

---

### User Story 4 - 太字ショートカット (Priority: P3)

ユーザーがテキストを選択してCmd/Ctrl+Bを押すと、選択範囲が`**`でラップされて太字マークダウン記法になる。

**Why this priority**: 執筆効率を上げる便利機能だが、手動で`**`を入力しても同じ結果が得られるため、優先度は低い。

**Independent Test**: テキストを選択し、Cmd/Ctrl+Bを押して`**選択テキスト**`に変換されることを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーがテキストを選択している, **When** Cmd/Ctrl+Bを押す, **Then** 選択範囲が`**`でラップされる
2. **Given** テキストが選択されていない, **When** Cmd/Ctrl+Bを押す, **Then** カーソル位置に`****`が挿入され、カーソルが中央に移動する
3. **Given** 選択範囲が既に`**`でラップされている, **When** Cmd/Ctrl+Bを押す, **Then** `**`が除去される（トグル動作）

---

### User Story 5 - 保存状態の通知 (Priority: P2)

ユーザーは、保存が完了したこと、または保存中にエラーが発生したことを視覚的に確認できる。トースト通知により、ユーザーは現在の状態を把握できる。

**Why this priority**: フィードバックがないと、ユーザーは保存されたか不安になる。信頼性の認知に重要。

**Independent Test**: 自動保存または手動保存後に、画面上に通知が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 自動保存または手動保存が成功した, **When** 保存処理が完了する, **Then** 成功を示すトースト通知が表示される
2. **Given** 保存が失敗した, **When** エラーが発生する, **Then** エラーを示すトースト通知が表示される
3. **Given** トースト通知が表示された, **When** 3秒経過する, **Then** 通知が自動的に消える

---

### Edge Cases

- 連続した自動保存リクエストが発生した場合、最新の内容のみが保存される（デバウンスにより古いリクエストはキャンセル）
- IndexedDBへの書き込み中にブラウザが閉じられた場合、最後に完了した保存時点の内容が復元される
- ファイル切替時に未保存の変更がある場合、自動保存が即座に実行される
- ショートカットキーが他のブラウザ拡張機能と競合した場合、アプリ内のショートカットが優先される
- 非常に長い文章（20,000文字以上）でもデバウンスにより入力が妨げられない

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: システムは、入力停止後700〜1200msでアクティブファイルの内容をIndexedDBに自動保存しなければならない
- **FR-002**: システムは、プレビュー更新を100〜250msのデバウンスで制御しなければならない
- **FR-003**: システムは、自動保存とプレビュー更新を別々のタイマーで管理しなければならない
- **FR-004**: ユーザーはCmd/Ctrl+Sで現在のファイルを即座に保存できなければならない
- **FR-005**: ユーザーはCmd/Ctrl+Bで選択テキストを太字記法でラップできなければならない
- **FR-006**: システムは、保存成功時に成功通知を表示しなければならない
- **FR-007**: システムは、保存失敗時にエラー通知を表示しなければならない
- **FR-008**: 通知は表示後3秒で自動的に消えなければならない
- **FR-009**: システムは、ブラウザのデフォルトショートカット動作（Cmd/Ctrl+Sによる保存ダイアログ等）を抑制しなければならない
- **FR-010**: システムは、未保存の変更を示すフラグ（isDirty）を管理し、保存完了時にリセットしなければならない
- **FR-011**: システムは、起動時に最後に保存された内容を復元しなければならない

### Key Entities

- **AutosaveTimer**: 自動保存のスケジューリングを管理。デバウンス間隔、最後の保存時刻、保留中の保存リクエストを追跡
- **PreviewTimer**: プレビュー更新のスケジューリングを管理。デバウンス間隔と保留中の更新リクエストを追跡
- **Toast**: 通知メッセージを表す。タイプ（成功/エラー）、メッセージ内容、表示時間を持つ
- **AppState.isDirty**: 現在のファイルに未保存の変更があるかを示すフラグ
- **AppState.lastSavedAt**: 最後に保存が完了した時刻

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: ユーザーが入力を停止してから1.5秒以内に自動保存が完了する
- **SC-002**: 連続入力中（毎秒10キーストローク）でも、入力遅延を体感しない（目安: キー入力から表示まで50ms以内）
- **SC-003**: ブラウザをリロードした後、直前の編集内容が100%復元される
- **SC-004**: 5,000〜20,000文字の文章でも、入力とプレビュー更新がスムーズに動作する
- **SC-005**: 保存完了通知が100%の保存操作で表示される
- **SC-006**: ショートカット（Cmd/Ctrl+S、Cmd/Ctrl+B）が95%以上の環境で正常に動作する

## Assumptions

- IndexedDBは既にSprint 3で実装済みであり、ファイルの読み書きAPIが利用可能
- プレビュー更新の仕組みは既にSprint 2で実装済みであり、デバウンスを追加するだけで対応可能
- ユーザーは一般的なデスクトップブラウザ（Chrome、Firefox、Safari、Edge）を使用している
- モバイルブラウザではCmd/Ctrl+Sなどのショートカットは利用されないため、モバイル対応は必須ではない
