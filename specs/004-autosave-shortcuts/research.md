# Research: 自動保存・デバウンス・ショートカット

**Feature**: 004-autosave-shortcuts
**Date**: 2025-12-28

## 1. 既存実装の分析

### 1.1 previewService.js のデバウンス実装

**現状**:

- デバウンス関数が既に実装済み（`debounce(callback, delay)`）
- `DEFAULT_DEBOUNCE_DELAY = 150` でプレビュー更新を制御
- `cancel()` メソッドでタイマーをクリア可能

**決定**: 既存のデバウンス関数を再利用する
**根拠**: 動作実績あり、新規実装の必要なし
**代替案**: 汎用ユーティリティとして切り出す → 現時点では不要（YAGNI）

### 1.2 fileService.js の状態管理

**現状**:

- `state.isDirty` が既に実装済み
- `state.activeFile` でアクティブファイルを追跡
- `saveCurrentFile()` が保存ロジックを持つ（isDirty=falseの場合はスキップ）
- コールバック `onError` でエラー通知が可能

**決定**: 自動保存は `saveCurrentFile()` を呼び出すラッパーとして実装
**根拠**: 保存ロジックの重複を避け、isDirty管理を一元化
**代替案**: 自動保存専用の保存メソッドを作成 → 不要（既存で十分）

### 1.3 bindings.js のイベント処理

**現状**:

- `handleInput` で入力時に `fileService.updateContent()` と `previewController.update()` を呼び出し
- ショートカット処理は未実装

**決定**: bindings.js にショートカットハンドラを統合
**根拠**: イベント処理の一元管理、Separation of Concerns維持
**代替案**: shortcutService.jsに分離 → 責務分離のため採用

## 2. 技術的決定事項

### 2.1 デバウンス間隔

| 処理           | 間隔   | 根拠                                                       |
| -------------- | ------ | ---------------------------------------------------------- |
| プレビュー更新 | 150ms  | 既存実装（憲法の100〜250ms範囲内）                         |
| 自動保存       | 1000ms | 憲法の700〜1200ms範囲の中央値、IndexedDB書き込み頻度を抑制 |

**決定**: プレビュー150ms、自動保存1000msで実装
**代替案**: 動的調整（負荷に応じて間隔変更）→ 複雑化するため不採用

### 2.2 ショートカット実装方式

**選択肢**:

1. `keydown` イベントで `metaKey || ctrlKey` を判定
2. KeyboardEvent.key を使用（ブラウザ間互換性）
3. event.code を使用（物理キー位置）

**決定**: `keydown` + `event.key` + `(metaKey || ctrlKey)` を採用
**根拠**:

- macOS: `metaKey` (⌘)
- Windows/Linux: `ctrlKey`
- `event.key` はロケール対応で "s", "b" を判定可能

**ブラウザ対応**:

- Chrome, Firefox, Safari, Edge: 全対応
- `event.preventDefault()` でブラウザデフォルト動作を抑制

### 2.3 トースト通知実装

**選択肢**:

1. 固定位置のDOM要素を動的に追加/削除
2. CSS Transitionでフェードイン/アウト
3. 複数通知のスタック表示

**決定**: 単一トースト + CSSアニメーション
**根拠**:

- 自動保存通知は頻繁に発生するため、複数スタックは不要
- 新しい通知は前の通知を上書き
- シンプルさ優先（YAGNI）

**仕様**:

- 位置: 画面右下
- 表示時間: 3秒（エラーは5秒）
- タイプ: success / error
- 自動保存時は「保存しました」、手動保存時は「保存完了」

### 2.4 太字ショートカット（Cmd/Ctrl+B）

**実装方式**:

1. `textarea.selectionStart` / `selectionEnd` で選択範囲取得
2. 選択テキストを `**text**` でラップ
3. カーソル位置を調整

**トグル動作**:

- 選択範囲が既に `**...**` でラップされている場合は除去
- 正規表現 `/^\*\*(.*)\*\*$/` でチェック

**決定**: 選択範囲ベースの実装、トグル対応
**代替案**: execCommand（非推奨API）→ 不採用

### 2.5 ファイル切替時の自動保存

**現状**: `fileService.selectFile()` 内で `saveCurrentFile()` を呼び出し済み

**決定**: 追加実装不要（既存で対応済み）
**確認事項**: 自動保存タイマーは切替時にキャンセルする必要あり

## 4. リスクと対策

### 4.1 自動保存とファイル切替の競合

**リスク**: 自動保存中にファイル切替が発生すると、間違ったファイルに保存される可能性

**対策**:

- 自動保存は `state.activeFile` の `id` をキャプチャしてから実行
- 保存実行時に現在のactiveFileと一致するか確認

### 4.2 連続キーストローク時のパフォーマンス

**リスク**: 高速入力時にタイマーリセットが頻発

**対策**:

- デバウンス実装により制御済み
- タイマーIDは単一変数で管理（複数タイマーの蓄積を防止）

### 4.3 ブラウザ拡張機能との競合

**リスク**: ブラウザ拡張がCmd+Sをフックしている場合

**対策**:

- `event.preventDefault()` を早期に呼び出し
- 競合時はアプリ側のショートカットを優先（仕様通り）
- 確実に動作するブラウザはChrome, Firefox, Safari, Edge
