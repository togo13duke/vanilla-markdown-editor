# Feature Specification: ファイル管理機能

**Feature Branch**: `003-file-management`
**Created**: 2025-12-27
**Status**: Draft
**Input**: User description: "Sprint 3: ファイル管理（IndexedDB / File API）- 複数ファイルを扱える状態を作る"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新規ファイル作成 (Priority: P1)

ユーザーは新しいMarkdownファイルを作成し、すぐに編集を開始できる。サイドバーの「新規作成」ボタンをクリックすると、新しいファイルがファイルリストに追加され、エディタにフォーカスが移動する。

**Why this priority**: ファイル管理の最も基本的な機能であり、この機能なしには複数ファイルを扱うことができない。すべての他の機能の前提条件となる。

**Independent Test**: 新規作成ボタンをクリックし、ファイルがリストに表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** サイドバーが表示されている状態で、**When** 新規作成ボタンをクリックする、**Then** 新しいファイルがファイルリストに追加され、エディタが空の状態で表示される
2. **Given** 既存のファイルを編集中の状態で、**When** 新規作成ボタンをクリックする、**Then** 現在のファイルの内容は保持され、新しい空のファイルに切り替わる
3. **Given** 新規ファイルを作成した直後、**When** ブラウザをリロードする、**Then** 作成したファイルがファイルリストに表示される（永続化されている）

---

### User Story 2 - ファイル切替 (Priority: P1)

ユーザーは複数のファイルを切り替えながら編集できる。サイドバーのファイルリストからファイルをクリックすると、そのファイルの内容がエディタに表示される。

**Why this priority**: 複数ファイル管理の中核機能。ファイル作成と同様に、この機能がなければ複数ファイルを扱う意味がない。

**Independent Test**: 複数のファイルを作成し、それぞれをクリックして内容が正しく切り替わることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数のファイルが存在する状態で、**When** ファイルリストの別のファイルをクリックする、**Then** エディタの内容がクリックしたファイルの内容に切り替わる
2. **Given** ファイルAを編集してファイルBに切り替えた後、**When** ファイルAを再度選択する、**Then** ファイルAの編集内容が保持されている
3. **Given** ファイルを編集中の状態で、**When** 別のファイルに切り替える、**Then** 切り替え前のファイルは自動的に保存される

---

### User Story 3 - ファイルの永続化（ブラウザ再起動後の復元） (Priority: P1)

ユーザーはブラウザを閉じて再度開いても、作成したファイルと編集内容が失われない。アプリを再起動すると、前回のファイルリストと内容がすべて復元される。

**Why this priority**: データ消失はブロッカー扱い（sprint.mdより）。ユーザーの作業を保護する最も重要な機能。

**Independent Test**: ファイルを作成・編集し、ブラウザをリロードして内容が復元されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ファイルを作成して内容を入力した状態で、**When** ブラウザをリロードする、**Then** ファイルリストと各ファイルの内容が完全に復元される
2. **Given** 複数のファイルが存在する状態で、**When** ブラウザを完全に閉じて再度開く、**Then** すべてのファイルが前回の状態で復元される

---

### User Story 4 - ファイル削除 (Priority: P2)

ユーザーは不要になったファイルを削除できる。削除前に確認ダイアログが表示され、誤削除を防止する。

**Why this priority**: ファイル管理の基本機能だが、作成・切替・永続化が先に必要。

**Independent Test**: ファイルを削除し、リストから消えることを確認できる。

**Acceptance Scenarios**:

1. **Given** ファイルが存在する状態で、**When** ファイルの削除ボタンをクリックする、**Then** 確認ダイアログが表示される
2. **Given** 確認ダイアログが表示されている状態で、**When** 削除を確認する、**Then** ファイルがリストから削除され、永続ストレージからも削除される
3. **Given** 確認ダイアログが表示されている状態で、**When** キャンセルを選択する、**Then** ファイルは削除されずに残る
4. **Given** 現在編集中のファイルを削除した後、**When** 削除が完了する、**Then** 他のファイルが自動的に選択される（ファイルがない場合は空の状態）

---

### User Story 5 - ファイルのエクスポート（.mdダウンロード） (Priority: P2)

ユーザーは編集したファイルを.mdファイルとしてローカルにダウンロードできる。これにより、ブラウザ外でもファイルを使用できる。

**Why this priority**: エクスポートはsprint.mdで明記されているスコープ。インポートより優先。

**Independent Test**: エクスポートボタンをクリックし、.mdファイルがダウンロードされることを確認できる。

**Acceptance Scenarios**:

1. **Given** ファイルを編集中の状態で、**When** エクスポートボタンをクリックする、**Then** ファイル名.md形式でファイルがダウンロードされる
2. **Given** ファイルタイトルが「README」の場合、**When** エクスポートする、**Then** 「README.md」というファイル名でダウンロードされる
3. **Given** ファイル内容にMarkdown記法が含まれている場合、**When** エクスポートする、**Then** 内容がそのまま（変換なしで）保存される

---

### User Story 6 - ファイル名の編集 (Priority: P2)

ユーザーはファイル名を変更できる。サイドバーのファイル名をダブルクリックまたは編集ボタンで名前を変更できる。

**Why this priority**: ファイル管理の利便性向上。デフォルトの「無題」から意味のある名前に変更できる。

**Independent Test**: ファイル名を変更し、リストに反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ファイルがリストに表示されている状態で、**When** ファイル名をダブルクリックする、**Then** ファイル名が編集可能な状態になる
2. **Given** ファイル名を編集中の状態で、**When** 新しい名前を入力してEnterを押す、**Then** ファイル名が更新される
3. **Given** ファイル名を編集中の状態で、**When** Escapeを押す、**Then** 編集がキャンセルされ元の名前に戻る

---

### Edge Cases

- **ファイルが0件の場合**: 初回起動時またはすべて削除後、適切な空状態メッセージを表示する
- **ストレージ容量不足**: IndexedDBの容量制限に達した場合、ユーザーにエラーメッセージを表示し、不要なファイルの削除を促す
- **同名ファイルの作成**: 同じ名前のファイルが既に存在する場合でも作成を許可する（内部IDで一意性を保証）
- **非常に長いファイル名**: 表示上は省略し、ツールチップで全体を表示する
- **ブラウザのプライベートモード**: IndexedDBが利用できない場合、警告メッセージを表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは新しいMarkdownファイルを作成できなければならない
- **FR-002**: システムはファイルの一覧を表示できなければならない
- **FR-003**: システムはファイルの内容を読み込み、エディタに表示できなければならない
- **FR-004**: システムはファイルの内容を更新できなければならない
- **FR-005**: システムはファイルを削除できなければならない
- **FR-006**: システムはファイルをブラウザのIndexedDBに永続化しなければならない
- **FR-007**: システムはブラウザ再起動後にすべてのファイルを復元できなければならない
- **FR-008**: システムは現在編集中のファイル（アクティブファイル）を追跡しなければならない
- **FR-009**: システムはファイルを.md形式でダウンロードできなければならない
- **FR-010**: システムはファイル名を変更できなければならない
- **FR-011**: システムは削除操作の前に確認を求めなければならない
- **FR-012**: システムはファイル切替時に現在のファイルを自動保存しなければならない

### Key Entities

- **FileEntity**: 単一のMarkdownファイルを表す
  - id: ファイルを一意に識別するID（UUID形式）
  - title: ファイル名（例: "README.md"）
  - content: Markdown本文
  - createdAt: 作成日時
  - updatedAt: 更新日時
  - sortKey: ファイルリストでの並び順

- **ActiveFile**: 現在編集中のファイルへの参照
  - 常に1つのファイルのみがアクティブ
  - ファイルがない場合はnull

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは10個以上のファイルを作成・管理できる
- **SC-002**: ブラウザを再起動しても100%のファイルとその内容が復元される
- **SC-003**: ファイルの切替操作は1秒以内に完了する
- **SC-004**: ユーザーは3クリック以内でファイルを新規作成できる
- **SC-005**: ユーザーは2クリック以内でファイルをエクスポートできる
- **SC-006**: 削除確認により誤削除を防止できる（確認なしの即時削除は発生しない）

## Assumptions

- ユーザーのブラウザはIndexedDBをサポートしている（モダンブラウザを前提）
- ファイル数は一般的な使用で100件程度を想定（極端に大量のファイルは想定外）
- ファイルサイズは1ファイルあたり最大1MB程度を想定
- ファイル名に使用できる文字に制限は設けない（表示の切り詰めのみ対応）
- 新規ファイル作成時のデフォルト名は「無題」とする
- ファイルリストの並び順は更新日時の降順（最新が上）とする
