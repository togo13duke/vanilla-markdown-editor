# Feature Specification: Markdownパーサ

**Feature Branch**: `002-markdown-parser`
**Created**: 2025-12-27
**Status**: Draft
**Input**: Sprint 2 - Markdownパーサ（正規表現・サブセット）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - リアルタイムMarkdownプレビュー (Priority: P1)

ユーザーがエディタにMarkdownテキストを入力すると、即座にプレビューペインに整形されたHTMLが表示される。これにより、ユーザーは入力内容がどのように表示されるかをリアルタイムで確認できる。

**Why this priority**: これはMarkdownエディタの中核機能であり、この機能なしではエディタとしての価値がない。ユーザーが最も頻繁に使用する機能である。

**Independent Test**: エディタにMarkdownテキストを入力し、プレビューペインに正しく整形されたHTMLが表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** エディタが空の状態, **When** ユーザーが「# 見出し」と入力する, **Then** プレビューに大きな見出しテキストが表示される
2. **Given** エディタにテキストがある状態, **When** ユーザーがテキストを編集する, **Then** プレビューが更新内容を反映する
3. **Given** エディタにMarkdownがある状態, **When** ユーザーが入力を続ける, **Then** プレビューが遅延なく更新される

---

### User Story 2 - XSSからの保護 (Priority: P1)

ユーザーが悪意のあるコードを含むテキストを入力しても、アプリケーションはそのコードを実行せず、安全に表示する。これにより、ユーザーのセキュリティが保護される。

**Why this priority**: XSS脆弱性はセキュリティ上の重大なリスクであり、MVPから必須要件として扱う。ユーザーの信頼とデータ保護に直結する。

**Independent Test**: `<script>alert('XSS')</script>`などの悪意のあるコードを入力し、スクリプトが実行されずにテキストとして表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** エディタが空の状態, **When** ユーザーが`<script>alert('XSS')</script>`と入力する, **Then** スクリプトは実行されず、テキストとしてエスケープ表示される
2. **Given** エディタにテキストがある状態, **When** ユーザーがHTMLタグ（例: `<div onclick="alert('XSS')">click</div>`）を入力する, **Then** イベントハンドラは無効化されテキストとして表示される
3. **Given** リンク記法を使用する状態, **When** ユーザーが`[link](javascript:alert('XSS'))`と入力する, **Then** `javascript:`スキームは拒否またはサニタイズされる

---

### User Story 3 - 基本的なMarkdown記法のサポート (Priority: P1)

ユーザーは見出し、太字、斜体、リンク、コードブロックといった基本的なMarkdown記法を使用して、テキストを整形できる。

**Why this priority**: これらは最も一般的に使用されるMarkdown機能であり、基本的な文書作成に必要不可欠である。

**Independent Test**: 各記法を個別に入力し、正しく整形されることを確認できる。

**Acceptance Scenarios**:

1. **Given** エディタが空の状態, **When** ユーザーが`# 見出し1`、`## 見出し2`...`###### 見出し6`と入力する, **Then** 各レベルに応じた見出しが表示される
2. **Given** エディタが空の状態, **When** ユーザーが`**太字**`と入力する, **Then** 太字テキストが表示される
3. **Given** エディタが空の状態, **When** ユーザーが`*斜体*`と入力する, **Then** 斜体テキストが表示される
4. **Given** エディタが空の状態, **When** ユーザーが`[リンクテキスト](https://example.com)`と入力する, **Then** クリック可能なリンクが表示される
5. **Given** エディタが空の状態, **When** ユーザーがバッククォートでコードを囲む, **Then** インラインコードまたはコードブロックとして表示される

---

### User Story 4 - 不正な入力への耐性 (Priority: P2)

ユーザーが不完全または不正なMarkdown記法を入力しても、アプリケーションはクラッシュせず、可能な限り意味のある表示を行う。

**Why this priority**: ユーザーは入力中に不完全なMarkdownを持つことが多く、エラーなく動作し続けることが重要である。

**Independent Test**: 不完全なMarkdown（閉じていない太字記号など）を入力し、アプリケーションがクラッシュせずに動作することを確認できる。

**Acceptance Scenarios**:

1. **Given** エディタにテキストがある状態, **When** ユーザーが`**太字`（閉じタグなし）と入力する, **Then** アプリケーションはクラッシュせず、入力をそのまま表示するか最善の解釈を行う
2. **Given** エディタにテキストがある状態, **When** ユーザーが`[リンク](不完全`と入力する, **Then** アプリケーションはクラッシュせず、テキストをそのまま表示する
3. **Given** 大量のテキストがある状態, **When** ユーザーが入力を続ける, **Then** アプリケーションは応答性を維持する

---

### Edge Cases

- 空のエディタ内容を変換するとどうなるか？→ 空のプレビューが表示される
- 非常に長い行（1000文字以上）を入力するとどうなるか？→ 正常に処理され表示される
- ネストされたMarkdown記法（例: `***太字かつ斜体***`）はどう処理されるか？→ サポート範囲内で適切に処理される
- 連続した特殊文字（例: `****`）はどう処理されるか？→ クラッシュせずにそのまま表示される
- Unicodeや絵文字を含むテキストはどう処理されるか？→ 正常に処理され表示される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはMarkdownテキストを安全なHTMLに変換しなければならない
- **FR-002**: システムは見出し記法（`#`から`######`まで）をサポートしなければならない
- **FR-003**: システムは太字記法（`**テキスト**`）をサポートしなければならない
- **FR-004**: システムは斜体記法（`*テキスト*`）をサポートしなければならない
- **FR-005**: システムはリンク記法（`[テキスト](URL)`）をサポートしなければならない
- **FR-006**: システムはインラインコード記法（`` `コード` ``）をサポートしなければならない
- **FR-007**: システムはコードブロック記法（``` ``` ```で囲まれたブロック）をサポートしなければならない
- **FR-008**: システムは出力前にすべての危険な文字（`<`, `>`, `&`, `"`, `'`）をエスケープしなければならない
- **FR-009**: システムはリンクのURLで`javascript:`スキームを拒否しなければならない
- **FR-010**: システムは不正または不完全なMarkdown入力でもクラッシュしてはならない
- **FR-011**: システムはエディタの入力変更時にプレビューを更新しなければならない

### Key Entities

- **MarkdownInput**: ユーザーがエディタに入力した生のMarkdownテキスト
- **HTMLOutput**: パーサが生成した安全なHTML文字列。プレビューペインに表示される
- **ParseResult**: パース処理の結果。HTMLと、将来的にはアウトライン情報（見出しリスト）を含む

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがMarkdownを入力すると、1秒以内にプレビューに反映される
- **SC-002**: サポートされるすべてのMarkdown記法（見出し、太字、斜体、リンク、コード）が100%正確に変換される
- **SC-003**: 悪意のある入力（XSS攻撃パターン）が100%ブロックされる
- **SC-004**: 不正なMarkdown入力を1000パターン与えても、アプリケーションクラッシュ率が0%である
- **SC-005**: 5,000文字以上の長文を入力しても、入力の応答性が維持される

## Assumptions

- パーサは正規表現ベースのサブセット実装とし、外部ライブラリは使用しない（学習目的のため）
- 現時点ではメインスレッドでのパース処理を許容する（Sprint 5でWorkerに移行予定）
- サポートするMarkdown記法は最小限のサブセット（見出し、太字、斜体、リンク、コードブロック）に限定する
- リスト、テーブル、画像などの高度な機能は将来のスプリントで検討する

## Dependencies

- Sprint 1のUIレイアウト（エディタペインとプレビューペイン）が完成していること
- エディタからの入力イベントを受け取れる仕組みがあること

## Out of Scope

- リスト（順序付き・順序なし）のサポート
- テーブル記法のサポート
- 画像埋め込みのサポート
- 脚注・引用ブロックのサポート
- シンタックスハイライト
- Web Worker対応（Sprint 5で実施）
